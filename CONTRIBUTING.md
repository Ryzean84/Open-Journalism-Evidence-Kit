# Contributing to the Open Journalism Evidence Kit

Thank you for considering a contribution. This project is built for a global community, and useful contributions do not require programming.

## Start here

1. Read the [README](README.md), [Global Decentralized Journalism Ecosystem](GLOBAL_JOURNALISM_ECOSYSTEM.md), and [Rights, Copyright, and Ethical Preservation Policy](RIGHTS_COPYRIGHT_AND_ETHICS.md).
2. Search existing issues and pull requests before opening a new one.
3. For a substantial change, open an issue or discussion first so maintainers and affected communities can review the need and risks.
4. Keep contributions small, documented, testable, and reversible where possible.

## Ways to participate

### Journalists and local communities
- Identify public-interest reporting and preservation needs.
- Suggest official public sources, public records portals, local archives, and regional datasets.
- Review whether workflows are practical and safe in local conditions.
- Report broken links, outdated information, missing context, or harmful assumptions.

### Archivists and librarians
- Review metadata and preservation practices.
- Suggest retention, cataloguing, and format guidance.
- Help identify stable institutional sources and permitted archival pathways.

### Translators and language communities
- Review terminology and translations.
- Add language tags and regional usage notes.
- Identify right-to-left, script, accessibility, and low-bandwidth needs.
- Never silently replace an original-language source with a translation.

### Researchers and fact-checkers
- Improve research methods, source evaluation, and reproducibility.
- Document uncertainty, conflicting evidence, and limitations.
- Add examples that demonstrate how a claim can be independently checked.

### Developers and security practitioners
- Improve schemas, tests, connectors, local-first tools, and interoperability.
- Document permissions, network behavior, dependencies, and side effects.
- Include tests and explain how to reproduce results.
- Never add credentials, tokens, private source material, or sensitive personal data.

### Designers and accessibility specialists
- Review accessibility, screen-reader support, keyboard navigation, low-bandwidth use, and mobile constraints.
- Help make interfaces understandable without assuming technical expertise.

## Contribution types

Use a focused issue or pull request for one of these:
- Documentation or translation
- Source metadata correction
- Schema or fixture change
- Bug report or reproducible test
- Accessibility improvement
- Security or privacy improvement
- Integration proposal
- Research note or evaluation
- New language, region, or community need

## Evidence and source requirements

When adding a public source, provide:
- Canonical URL and publisher or issuing authority.
- Date observed and publication/update date when available.
- Language and source type.
- Collection method and tool version, if applicable.
- Rights status; use `unknown` or `not_assessed` rather than guessing.
- Limitations, uncertainty, and any known correction or supersession.
- A reason the source is relevant to public-interest work.

A source being publicly reachable does not automatically grant permission to copy, mirror, translate, or republish it.

## Safety rules

- Do not submit confidential tips, leaked files, private correspondence, credentials, or protected source identities through public issues or pull requests.
- Do not publish precise locations or identifying details that could endanger a person.
- Do not use the project to dox, harass, stalk, threaten, or target people.
- Do not bypass access controls, paywalls, or technical restrictions.
- Do not claim that a hash, signature, archive capture, or automated analysis proves a statement is true.
- Separate source material, observation, inference, translation, commentary, and editorial conclusion.
- If a contribution could expose someone to harm, stop and seek private review before submitting it.

## Pull request checklist

- [ ] The change has one clear purpose.
- [ ] Relevant documentation is updated.
- [ ] Tests or validation fixtures are included where appropriate.
- [ ] Sources, licenses, and attribution are recorded.
- [ ] Privacy, safety, and rights implications are considered.
- [ ] Uncertainty and limitations are stated.
- [ ] No secrets or sensitive source information are included.

## Review and recognition

Review focuses on correctness, safety, accessibility, reproducibility, and usefulness—not political viewpoint, contributor popularity, or contribution volume. Good-faith corrections are welcome. Maintainers may request changes, decline unsafe submissions, or pause work for independent review.

By contributing, you agree to follow the project [Code of Conduct](CODE_OF_CONDUCT.md).
